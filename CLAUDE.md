This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Grade-tracking app for an apprenticeship program (Laravel + Inertia + Vue). Coaches/trainers monitor apprentice grades and training portfolios; apprentices submit grades and maintain a "formation file" (training portfolio). Two main feature areas: grade management and formation-file management. See `README.md` for full feature descriptions and `docs/workflows/` for the source business-process PDFs (in French) these features must follow.

Domain source-of-truth docs (read before touching grading/tree logic):
- `docs/adr/ADR.md` — architecture decisions (e.g. the MP/Matura grading variant is modeled as sibling nodes in one evaluation tree, not a separate tree)
- `docs/project-docs/grade_tree_IT.md`, `docs/project-docs/grade_tree_EC.md`, `docs/project-docs/IT-schema.mmd`, `docs/project-docs/EC-schema.mmd` — the grade tree structures per program
- `docs/project-docs/role_permissions.md` — authoritative permission matrix by role (Apprentice, Coach, Trainer, Admin, Super-Admin)
- `docs/project-docs/DoD.md` — Definition of Done
- `docs/user_stories/user_story_final.md`

## Stack

Laravel 13 (PHP 8.3+) · Inertia.js · Vue 3 · Vite 8 · Tailwind 4 · shadcn-vue · PostgreSQL. Dev environment runs via Laravel Sail (Docker). Auth is handled by Laravel Fortify.

## Commands

All PHP/artisan commands run inside Sail: `./vendor/bin/sail <cmd>`. JS package manager is pnpm.

```bash
# Start environment
./vendor/bin/sail up -d
./vendor/bin/sail pnpm dev            # Vite dev server

# Tests (Pest)
./vendor/bin/sail artisan test
./vendor/bin/sail artisan test --filter=TestName
./vendor/bin/sail pest tests/Feature/HomeTest.php   # single file

# Lint / format
composer lint            # pint --parallel (write)
composer lint:check      # pint --parallel --test (check only)
pnpm check                # frontend lint (eslint etc.)
pnpm check:fix

# Static analysis
composer types:check     # phpstan (larastan) via phpstan.neon, level 7
pnpm types:check           # vue-tsc --noEmit

# Full CI-equivalent check (lint + types + tests, both stacks)
composer ci:check
composer test             # config:clear + lint:check + types:check + artisan test
```

No test runner is configured on the JS side yet (`README.md`/`technical_details.md` mention Vitest + Vue Testing Library as the intended choice, not yet wired up).

## Architecture notes

- **Inertia, not a JSON API.** Controllers return `Inertia::render(...)`; pages live in `resources/js/pages/*.vue` and map 1:1 to server routes. There is no separate SPA router — Inertia + `routes/web.php` (plus feature route files like `routes/profile.php`) own navigation.
- **Wayfinder-generated routes/actions.** `resources/js/routes/` and `resources/js/actions/` are generated by `laravel/wayfinder` from the backend routes/controllers — don't hand-edit these, they mirror `routes/*.php` and controller method signatures. Regenerate via the wayfinder Vite plugin (`@laravel/vite-plugin-wayfinder`) on build/dev.
- **shadcn-vue components** live under `resources/js/components/ui/*`; treat them as vendored (regenerate/re-add via the shadcn-vue CLI rather than hand-editing internals) and build feature UI in `resources/js/components/` / `resources/js/pages/` on top of them.
- **Static domain data** (grade tree definitions, months, MP vs. normal variants) is checked in as JSON under `resources/js/data/` (`modules.json`, `mp.json`, `normal.json`, `months.json`) rather than fetched — cross-reference with `docs/project-docs/grade_tree_*.md` when changing grading logic.
- **PostgreSQL specifics matter.** Unlike MySQL, Postgres does not auto-index foreign keys and ignores `->after()` column ordering in migrations; `$table->enum()` becomes `varchar + CHECK`, not a native enum. Add explicit indexes on FK columns used in lookups/deletes.
- **CarbonImmutable is the default date class** (configured in `AppServiceProvider`), not mutable `Carbon` — keep docblocks/type hints consistent with that.
- The domain model (grade evaluation tree, roles, formation file) is still early-stage: `docs/adr/ADR.md` and `docs/project-docs/role_permissions.md` describe the target design ahead of full implementation — check current `app/Models/` and `database/migrations/` state before assuming a described model/table exists.
